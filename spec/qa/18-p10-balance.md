# QA-группа — P10: эталонный баланс

**Загружать только при проверке затронутой системы.** Общий перечень и поиск ID — [`09-qa.md`](../09-qa.md) и [`test-index.tsv`](test-index.tsv).

## P10: эталонный баланс

| ID | Предметная проверка | Условие приёмки |
|---|---|---|
| `P10-T01` | Минимальная сложность, эталонный базовый защитник против четырёх `FK-GOBLIN`, воспроизводимые входы и тайминги | Защитник побеждает всех четырёх; исход одинаков при повторе; параметры сценария документируются, а не заменяются произвольным боем |
| `P10-T02` | Один `FK-GOBLIN` против самого слабого защитника | Уничтожение за **3 успешных удара**, примерно за **5 с** при нормальной скорости симуляции |
| `P10-T03` | Переход на ×2, ×3 и паузу во время эталонного боя | Логический исход тот же, 3 удара, корректные события урона и cooldown |
| `P10-T04` | Получение одинакового физического удара при разных значениях физической брони и неизменной магической броне | Итог снижается прямым вычитанием физической брони, не зависит от магической; итог неотрицателен |
| `P10-T05` | Получение одинакового магического удара при разных значениях магической брони и неизменной физической броне | Итог снижается прямым вычитанием магической брони, не зависит от физической; итог неотрицателен |
| `P10-T06` | Мгновенный и периодический физический/магический урон | Тип урона и временная схема — независимые параметры; порядок округления определён и проверен только после отдельного утверждения |
| `P10-T07` | Две миссии с разными `InitialSupplies` | Каждая начинает со своего значения, нет обязательного единого стартового бюджета |
| `P10-T08` | Межволновое начисление без настройки и с авторским переопределением | По умолчанию **10 припасов** после не-финальной волны, переопределение работает, после финальной награда не выдаётся |
| `P10-T09` | Разместить крестьянина и элитного гвардейца | **Одинаковая** стоимость размещения в припасах независимо от силы/ранга, без смешения с ценой изучения в городе |
| `P10-T10` | Убить обычного `FK-GOBLIN` и вражеского призванного | За обычного +**1** ресурс ловушек, за призванного +**0**, независимо от способа убийства |
| `P10-T11` | Перезарядить ловушку без индивидуальной цены и ловушку с override | По умолчанию **5** ресурса за полную зарядку; переопределение соблюдается; нельзя дозарядить при остатке >0 |
| `P10-T12` | Два типа союзных юнитов с разными `DeathCooldown` | Без override — **20 с**, с override — указанное время; бесплатное воскрешение и межволновое восстановление неизменны |
| `P10-T13` | Контрольные эффекты на разных типах атак | Индивидуальные замедления и оглушения по настройкам, общий ориентир 25–40% / 1–2 с не хардкодится |
| `P10-T14` | Слабое защищаемое сооружение и один атакующий гоблин | В эталонном сценарии объект выдерживает **>50 с** при ориентире 1 HP/удар через 1–1,5 с; другая миссия может иметь другое HP |
| `P10-T15` | Огненный шар и мощная ловушка по базовому гоблину | При успешном попадании достаточно урона для его уничтожения; для менее мощных ловушек такого обязательства нет |
| `P10-T16` | Тролль с малой регенерацией против слабой и более сильной обороны | Регенерация настраивается индивидуально; реальный исход и HP/с утверждаются автором по конкретному стат-блоку; не назначать автоподстройку |
| `P10-T17` | Параллельная проверка трёх сложностей на разных миссиях | Применяется **одинаковая общая модель сложности**, поверх которой действует собственный авторский сценарий миссии; коэффициенты остаются TBD P11 |
| `P10-T18` | Внести новый тип врага/юнита, ловушки, заклинания, миссии только через контентные данные | Параметры меняют конкретную систему, не требуют переписывать общий боевой код; формат данных выбрать в P18 |

**Критерий:** часть тестов — эталоны для будущего авторского контента, а не зелёные тесты существующей сборки. Пока точные стат-блоки/формула округления отсутствуют, соответствующие проверки помечены `PENDING DATA`, не `PASS`. Включить эти сценарии в полный полигон `PROD-GATE-001`.
