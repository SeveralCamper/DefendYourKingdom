# 00 — DefendYourKingdom: продукт и границы работ

> **Маршрут чтения:** сначала `README.md` и `AGENTS.md`. Этот файл — краткие рамки проекта, а не журнал обсуждений.

## Продукт

**DefendYourKingdom** — самостоятельная стратегия/Castle Defense для Steam на Unreal Engine 5.5. Вдохновение — «Осада: Битва за корону»; нельзя автоматически переносить механики из референса. Игровой цикл: **город** (сеточная территория, экономика, постройки, исследования, постоянный прогресс) ↔ **бой** (авторские 3D-маршруты, волны, оборонительные сооружения, мобильные в концепции ростера, но стационарные во время волны защитники, заклинания и герои). Игра должна оставаться доступной без обязательного доната.

## Версии и состояние

- **PRD подготовлен для исполнения**: игровые правила находятся в `spec/01…07`, предметные авторские паспорта — в `spec/catalog/`, технические требования — в `spec/tech/`, тесты — в `spec/qa/`, задачи — `12`, трассировка — `13`.
- **Документальная подготовка P19.01–P19.08 завершена.** Подтверждение комплекта автором и явный допуск Codex к работе — отдельная операция; текущее наличие PRD **не означает команду писать код**.
- **`AUDIT-00`** — первая операция *после допуска*: аудит фактического UE-проекта, компонентов, UE5.5 MCP, ассетов и сборки. В этом архиве игровых исходников нет, результаты аудита не подменять предположениями.
- **`M1-SLICE`** — работоспособный сокращённый цикл города и боя; **`M2-FULL`** — полный локальный играбельный DEV-MVP с временным лицензированным визуалом, все основные системы и полигон. Steam store page готовится **после M2-FULL**, не в M1/M2.
- **Первая реализация локальная:** без сервера, античита, онлайн-профиля, рейтингов, реплеев, Steamworks-интеграции и аудио. Контракты будущего онлайн-режима сохранены отдельно в технических файлах, но не являются заданиями M1/M2.
- **`PROD-GATE-001`:** игровые системы → рабочий тестовый полигон на черновой первой карте → автоматические и ручные тесты → явное `POLYGON_ACCEPTED` автора → только затем создание **финальных** кампанийных/бесконечных карт. Первую реальную миссию можно завершать после приёмки.

## Неподменяемые правила разработки

1. **Авторские значения конкретных типов не заменяются примерами.** Если поле не заполнено, для локального DEV-MVP допустимо только заменяемое значение `DEV_PLACEHOLDER`, отдельно от паспорта. Финальный контент требует авторского паспорта (`CONTENT-GATE-001`). Неизвестное поле не создаёт права изменять механику.
2. **Изменения PRD не требуют бюрократии «заморозки».** Читать актуальные файлы при работе; реализацию приводить к новым авторским решениям и тестировать затронутые системы.
3. Конкретные механики и эффекты едины для игры; подробности всегда читать в тематических спецификациях, а не извлекать из этого обзора.
4. Индивидуальные карты/волны и числовой баланс там, где не заполнены, не выдавать за утверждённые; для разработки использовать конфигурируемые временные данные, а не постоянные условные числа.
5. Строительство, улучшения и исследования **имеют таймеры и очереди**; в DEV-MVP временными могут быть **длительности**, но не сама механика.
6. Плоская физическая/магическая броня — `max(0, входящий урон − подходящая броня)`. Все продолжительные боевые эффекты завершаются на границе волны. В испытании `CHALLENGE_5` у **всех** защищаемых объектов HP=1.
