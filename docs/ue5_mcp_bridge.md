# 🔌 Unreal Engine 5 MCP Мост и Инструменты

Как ИИ-агент, ты взаимодействуешь с проектом через плагин **Unreal Model Context Protocol (MCP)**. Соблюдай следующие правила безопасности.

## 1. Доступные инструменты Агента (Интерфейс MCP)
У тебя есть доступ на чтение и запись в локальную среду разработки через следующие схемы:
* `ue_compile_project`: Запускает Unreal Build Tool (UBT) через Live Coding или стандартную сборку.
* `ue_inspect_actor`: Инспектирует компоненты, свойства и иерархию открытого ассета Actor.
* `ue_modify_property`: Программно изменяет свойства `UPROPERTY` на целевых объектах CDO (Class Default Objects).
* `ue_generate_class`: Генерирует чистые заголовочные файлы (`.h`) и файлы реализации (`.cpp`) строго по стандартам кодинга Epic Games.

## 2. Правила компиляции и безопасности кода
* **Гигиена заголовков:** Всегда включай `"CoreMinimal.h"`, `"GameFramework/Actor.h"` и файл `.generated.h` строго последним в списке инклудов.
* **Управление памятью:** Все сырые указатели на объекты `UObject` внутри заголовочных файлов должны быть обернуты в `TObjectPtr<T>` и снабжены макросом `UPROPERTY()`, чтобы избежать случайной очистки сборщиком мусора (Garbage Collector).
* **Безопасность Live Coding:** Если ты вносишь изменения в структуры заголовков (`.h`), меняющие разметку памяти (добавление новых полей класса, изменение сигнатур функций), явно попроси человека-оператора перезагрузить редактор и сделать чистый билд, не полагаясь только на Live Coding.
* **Отражение для C++:** Blueprint-классы и Blueprint-визуализация проектом не используются. Добавляй UPROPERTY/UFUNCTION-отражение только там, где оно нужно системам UE (например, GC, сериализация, компоненты и UMG на C++); не добавляй Blueprint-события или Blueprint-спецификаторы для неиспользуемых визуальных классов.
