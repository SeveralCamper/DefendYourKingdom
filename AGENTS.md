# 🤖 AI Agent Deployment & Project Context

## Контекст проекта
- Проект называется **Defend Your Kingdom**. Это десктопная игра в жанре Castle Defense на движке Unreal Engine 5 (C++) для Steam, создаваемая по мотивам классической игры «Осада: Битва за Корону».
- Считай существующий код, конфигурацию и документацию источником истины; не выводи стек и архитектуру только из названия.

## 📁 Документация и Архитектура проекта
Перед внесением любых изменений в код, обязательно изучи спецификации и архитектурные контракты в папке `docs/`:
1. 🔄 **[Gameplay Loop Specification](docs/gameplay_loop.md)** — разбор макро-цикла цитадели и микро-цикла боевой сессии.
2. 📐 **[Architectural Design Patterns](docs/architecture_patterns.md)** — правила использования Data-Driven дизайна, нативных компонентов UE5, фабрик и делегатов.
3. 🔌 **[Unreal Engine 5 MCP Bridge & Tooling](docs/ue5_mcp_bridge.md)** — ограничения безопасности при работе через Model Context Protocol, правила работы с памятью (`TObjectPtr`) и Live Coding.

## Работа с кодом
- Перед изменениями изучи связанные файлы и следуй принятым в проекте соглашениям.
- Делай узкие изменения; не добавляй зависимости и несвязанные рефакторинги без необходимости.
- Уважай разделение между чистой игровой логикой (C++) и визуальным представлением (Ассеты/Блупринты). Данные баланса выноси в `UDataAsset` и `UDataTable`.
- Уточняй требования, только если неоднозначность влияет на поведение, архитектуру или формат данных. Иначе выбери минимальное решение и обозначь предположение.

## Проверки
- Используй команды сборки и проверок, указанные в файлах проекта; не выдумывай команды.
- Всегда используй тулсеты MCP (например, `ue_compile_project`) для валидации измененного кода.
- В итоговом ответе перечисли изменения и результаты выполненных проверок.

## Подход к Git
- Работать в текущей ветке. Новые ветки создавать только по прямому запросу пользователя.
- Комменатрии к комиту оставлять обязательно в таком формате: "Task-xxx: <что сделано в этом коммите>", xxx - номер задачи.
