# Правила версионирования Defend Your Kingdom

**Формат:** `a.b.c.d`.

## Значение компонентов

- **`a` — релиз продукта.** Увеличивается только при выпуске релизной версии игры.
- **`b` — завершённый этап разработки.** Увеличивается, когда полностью закрыт этап из [плана задач MVP](mvp_task_plan.md). Этап считается закрытым, когда выполнены его задачи и критерии готовности.
- **`c` — добавление или изменение.** Увеличивается, когда в проект добавлена новая возможность или изменена существующая (`Added` / `Changed`).
- **`d` — исправление ошибки.** Увеличивается только при исправлении бага (`Fixed`). Добавления и изменения сами по себе `d` не меняют.

## Текущее состояние

В проекте пока нет опубликованного релиза и ни один этап плана MVP не закрыт, поэтому `a = 0` и `b = 0`. Записи `Added`/`Changed` в журнале дают текущую рабочую версию `0.0.3.0`; исправлений багов, требующих увеличения `d`, пока нет.

Записи в [Changelog.md](../Changelog.md) отражают историю репозитория:

- `2211086 Initial commit` — первое добавление README, `0.0.1.0`.
- `c37e6dd Task-001: Add initial documentation and AGENTS.md` — добавление стартовой документации, `0.0.2.0`.
- Текущая документационная правка с планом задач — `0.0.3.0`.

## Сброс младших компонентов

При увеличении компонента все компоненты справа обнуляются:

- `a` увеличен при выпуске релиза → `b = 0`, `c = 0`, `d = 0`.
- `b` увеличен при закрытии этапа → `c = 0`, `d = 0`.
- `c` увеличен при добавлении/изменении → `d = 0`.
- `d` увеличивается при исправлении бага; других компонентов справа нет.

Текущая версия остаётся `0.0.3.0`: более крупный компонент пока не увеличивался.
